结论先行

新版均分相对旧版为 +0.015384。LoopX main 的明确收益集中在“可把前沿写进文件或 Todo”的任务：阶段号、棋盘、已过检查、待修模块能被下一次 fresh exec 可靠恢复。它并不会自动提高领域答案正确率，也不会获得隐藏 verifier 的具体失败原因。

最关键的负例是 duckdb-optimizer-closure：LoopX 先推动出 correctness 安全版本，但后续 phase 为追求性能覆盖了它，最终触发零容差 correctness gate。说明当前机制擅长继续工作，却缺少 best-so-far checkpoint + final rollback。因此“Todo/replan 真实运行”与“最终 reward 提高”必须分开判断。

因果限制：这是两个已完成轨迹集合的 matched task 对比，不是同随机种子 A/B。新版 6 题采用显式正式重跑覆盖，且部分预算比旧版长。报告只把可由轨迹和 verifier 证明的行为链列为事实，其余只作为机制解释。

当前跑法与旧版差异

旧 heartbeat

LoopX 0.5.3 路径，Codex 0.153.4 app-server，native Goal 开启。

Harbor phase
  → thread/start + thread/goal/set
  → thin dispatcher 写进 native Goal
  → turn/start / Goal continuation
  → 同一 thread 在 phase 内保留对话上下文
  → Harbor interim/final verifier

优势是连续对话记忆；风险是通用 onboarding/project-map 可能占用任务预算，native Goal 的 complete/blocked 也可能过早收束。

LoopX main heartbeat

LoopX commit 1c7b40e，Codex 0.154.0，generic_cli，native Goal 关闭。

Harbor phase
  → task.md + trial-local Goal + claimed P0 Todo
  → external_scheduler_worker
  → heartbeat-prompt --thin
  → fresh codex exec (resume=false)
  → refresh/writeback/settlement
  → workspace + registry 跨 wake 保留
  → Harbor interim/final verifier

每个 wake 都是新模型会话；只有工作区和 LoopX registry 是跨 wake 记忆。replan_after_completed_todos=3 是审查阈值，不是每三个工具调用 replan，也不会自动回滚第三个 Todo。

两层循环不能混用：Harbor phase 是外层“执行 agent → interim verifier → 决定是否继续”的循环；LoopX wake 是一个 phase 内由 scheduler 发起 fresh Codex 的内层循环。进入新 phase 时聊天上下文不继承，但同一 trial 的工作区和 trial-local registry 仍在，并写入新的 phase Todo。Todo cadence replan 统计合格完成的 advancement Todo，不按 wake 数或 phase 数触发。

LoopX main 机制判断

Todo 的有效作用

把当前 phase 绑定为 claimed P0，并允许模型写 successor，使下一轮不依赖旧聊天就能恢复阶段前沿。APEX law/management、2048、chess 是强证据。

Replan 的边界

audio-visual 中 cadence replan 确实把假终态重新打开，但没有隐藏 schema 反馈，只能扩大合理尝试面；最终 reward 几乎不变。

Fresh exec 的取舍

隔离旧指令和上下文漂移，状态更可审计；代价是每次重读 skill/registry，且隐含领域口径若未写回文件就会丢失。

当前最大缺口

没有按正式 correctness 维护最高有效 checkpoint。DuckDB 表明继续推进可能把安全实现换成高性能但非确定的版本。
